# Конфигуратор Zeekr 9X

Только конфигуратор: без шапки, логотипа, подвала и цен. Его собирают в сборку и встраивают в страницу модели на сайте.

Посмотреть: https://tema-mail.github.io/zeekr-9x-konfigurator/ (закрыт от индексации).
Локально: `python3 -m http.server 8932`, затем http://127.0.0.1:8932/

## Что выбирает человек
Места (6 или 5), версия (Max, Ultra, Hyper, «Яохэй»), батарея 55 или 70 кВт·ч, пакет помощи водителю H7 или H9,
цвет кузова (6), декор кузова (до 5), диски (актуальные 22″ кованые: «Синъяо» с 4- или 6-поршневыми суппортами,
зеркальные, чёрные «Яохэй»), цвет салона, один или два передних экрана, поворотные кресла второго ряда и фаркоп.
20″ и 21″ «Синмай» (Max, Ultra) – заводские диски, которые Zeekr сейчас по акции меняет на 22″; в конфигураторе они есть с этой пометкой.

Правила совместимости взяты из официального конфигуратора: глянцевый хром – только с белым кузовом,
чёрный декор и пакет «Яохэй» – только с чёрным, чёрные диски – только в пакете «Яохэй». Выбор подстраивается сам.

## Картинки
Официальные рендеры Zeekr конкретной сборки (zeekrlife.com, раздел заказа): главный кадр без фона, три студийных ракурса
(спереди ¾, сбоку, сзади ¾) и салон. На картинке всегда тот цвет, декор, диски и лидары, которые выбраны.
86 сборок кузова × 4 кадра + 18 вариантов салона, всё в WebP: `img/zeekr-9x/ext/{H7|H9}_{цвет}_{декор}_{диски}--{вид}.webp`.

## Встраивание в сайт
Скопировать блок `<div class="z9" data-z9>…</div>` из `index.html`, подключить `css/konfigurator.css`,
`js/zeekr-data.js`, `js/konfigurator.js`, положить рядом папку `img/`. Движок общий для всех моделей Zeekr,
модель задаёт только `js/zeekr-data.js` и картинки. Цвета – токены `--z9-*` в начале CSS (светлая и тёмная тема).

Заявка «Отправить сборку менеджеру»: у формы атрибут `data-endpoint` – адрес приёма заявок сайта,
туда уходит POST JSON `{name, phone, text, url, lines, source, page}`. Пока он пустой, заявка уходит событием:
```js
document.querySelector('[data-z9]').addEventListener('zeekr:lead', e => send(e.detail));
// текущая сборка в любой момент: window.ZeekrCfg.get()  → {text, lines, config, url}
// каждое изменение: событие 'zeekr:change'
```
Ссылку на политику конфиденциальности вписать в `a[data-policy]` формы. Сборка хранится в адресе (`#v=55&o=…`).

## Как обновить данные
Инструменты в `tools/` (нужны Python 3, Playwright, Pillow; запросы идут с российского или китайского адреса –
zeekrlife.com не отвечает адресам из Европы):
1. `sniat-opcii.py 10 GMY_9X_01` – открывает страницу заказа 9X и снимает версии и опции через их API → `z9x-raw.json`;
2. `svod.py z9x-raw.json model.json` – правила совместимости и список нужных кадров → `model.json`;
3. `skachat.py model.json <modelInfoId> raw` – скачивает кадры в `raw/` (6 потоков, повторы, ракурсы ищутся по всем версиям);
4. `kadry.py raw img/zeekr-9x` – WebP; `ikonki-dekora.py model.json img/zeekr-9x` – иконки декора из рендеров;
5. `dannye.py model.json js/zeekr-data.js "Zeekr 9X" 9X img/zeekr-9x 10` – данные для страницы (переводы названий в нём).

Данные сняты 11.11.2026, модель Zeekr 9X 2025–2026 модельного года (modelInfoId 10).

## Проверки перед выкладкой и после неё
Общий движок (`js/konfigurator.js`, `css/konfigurator.css`) один на все марки. После любой правки движка или сборщика проверяются все модели, не одна.
1. `python3 tools/proverka_kadrov.py <папка проекта>` – до выкладки: каждый кадр из данных есть на диске, не пустой и открывается
   (прерванная сборка оставляет файлы в 0 байт, хостинг отдаёт их как существующие).
2. `python3 tools/proverka_vps.py <адрес страницы> [папка для снимков]` – после выкладки, в браузере на сервере в Амстердаме (на маке браузер не запускается):
   все версии, опции и галочки, кадр соответствует выбранной сборке, все картинки открываются, ссылка восстанавливает сборку,
   форма закрыта без галочки согласия, ширина 390 px, нет иероглифов в тексте. Ответ – «ЧИСТО» или «ЕСТЬ ЗАМЕЧАНИЯ» со списком.
3. `python3 tools/obzor.py <папка проекта> <папка для листов>` – листы для просмотра глазами: КАЖДЫЙ разный кадр салона и кузов по всем версиям
   (все виды сборки по умолчанию и главный кадр каждого цвета). Смотреть до выкладки все листы, а не выборку: руль, сиденья, экраны,
   зеркала, диски на месте, машина не обрезана. Автоматическая проверка этого не видит: у Xiaomi салон собирается из слоёв, и без скрытого
   варианта «по умолчанию» выходил кадр без руля – файл целый, страница «чистая», а картинка неверная.
   С третьим параметром `vse` в листы идёт каждый разный кадр кузова, с названиями вариантов в подписи (так смотрится новая марка).
   Что нашёл только просмотр у Xpeng (12.11.2026): у L03 в шести версиях у отделок не было фото салона, а под видом второго ряда лежал
   вид на панель; у G9 на экране пассажира читалась китайская надпись; у P7 отделки салона шли в списке по два раза.
   На каждое теперь есть остановка сборки или автозамена в `tools/xpeng.py`, но новая марка принесёт своё – смотреть всё равно.
4. Кадры новой марки смотреть глазами на светлом и тёмном цвете: надписи на номерных рамках и шильдиках закрашиваются по координатам
   (MASKS в сборщике марки), у версии с другой внешностью координаты свои.

## Правила сборки в данных
`mutex` у варианта – с чем он не сочетается (вариант с вариантом, вариант с галочкой, галочка с галочкой). `need` у варианта – галочка,
без которой производитель его не делает. Движок сам ставит или снимает такую галочку, блокирует её и подписывает причину
(«идёт с выбранным вариантом», «не ставится с выбранным вариантом»); из двух несовместимых галочек остаётся отмеченная последней.
Проверка в браузере сверяет эти правила после каждого клика.
